# Как переписывать резюме под трек

## Структура (1–2 страницы)

1. **Шапка:** имя, целевая должность (= название трека), город / формат, контакты: телефон, email, Telegram, LinkedIn, GitHub.
2. **Summary (3–4 строки):** кто, сколько лет, ключевой стек, 1–2 самых сильных результата. Пишется под трек.
3. **Ключевые навыки:** 8–15 пунктов. Сначала то, что чаще всего встречается в целевых вакансиях.
4. **Опыт** (обратный хронологический порядок): компания, роль, даты; 3–6 пунктов на место; формула — *действие → что сделал → результат с цифрой*.
5. **Проекты / open source** — если есть и относятся к треку.
6. **Образование, языки, сертификаты** — коротко.

## Акценты по типам треков

| Тип трека | Что поднять наверх | Что сократить |
|---|---|---|
| Инженер (Senior/Lead/Staff) | архитектура, сложные задачи, производительность, надёжность, код | управление людьми — одной строкой |
| Тимлид / EM / Head | размер команды, найм, онбординг, процессы, сроки, связь с бизнесом | технические мелочи |
| Архитектор / Tech Lead / CTO | технические решения и их эффект, стратегия, долг, масштабирование, выбор стека | рутинные задачи |
| QA / DevOps / Data / Mobile / Frontend | инструменты и практики своей области, метрики качества и скорости | нерелевантный стек |

## Правила

- Опыт во всех версиях **один и тот же**. Меняются только формулировки, порядок и акценты. Даты и должности одинаковые.
- Официальная должность расходится с фактической ролью — писать официальную, фактическую роль показывать в пунктах: «фактически руководил командой из 5 человек».
- Цифр нет — спросить. Не помнит — писать без цифры, не придумывать.
- Пробелы короче 3 месяцев не объяснять. Длиннее — одной строкой: фриланс, учёба, проект, личные причины.
- Компании из `never_list` не упоминать. Их период закрыть так, как скажет пользователь.
- EN-версия — не дословный перевод. Естественный английский, глаголы в прошедшем времени: Built, Led, Reduced. Уровень английского указать честно.
- Ключевые слова целевых вакансий (ATS) использовать, только если они правда есть в опыте.
- Без фото, возраста и семейного положения, если рынок этого не требует.

## Проверка перед сдачей

- [ ] RU и EN версии одного трека совпадают по фактам
- [ ] Даты не пересекаются странно и не противоречат друг другу
- [ ] Контакты одинаковые во всех версиях
- [ ] Нет компаний из `never_list`
- [ ] Каждая цифра подтверждена пользователем
